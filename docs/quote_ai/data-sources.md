# QuoteAI data sources

Every source is one entry in [`config/quote_ai/ingest/sources.yml`](../../config/quote_ai/ingest/sources.yml), loaded by the ingestion
framework (`src/quote_ai/ingest`, AI-02) into bronze. Ingestion writes bronze only; silver and gold are built from it
(AI-03).

| Source | What | Where it comes from | Schedule | Bronze |
| --- | --- | --- | --- | --- |
| `gudid_full_release` | Every device in GUDID, current version | AccessGUDID delimited full release (pipe-delimited zip, about 400 MB, monthly) | once, or again to rebuild | `quote_ai_gudid_bronze.device_raw`, `identifiers_raw`, `device_sizes_raw`, `product_codes_raw`, `gmdn_terms_raw` |
| `gudid_daily_updates` | The device versions published that day | AccessGUDID daily update release (zip, not on every day) | daily | `quote_ai_gudid_bronze.daily_device_raw` |
| `gudid_api_device_history` | Every published version of the devices that changed | AccessGUDID REST API v3, device history | daily, after the files | `quote_ai_gudid_bronze.api_device_history` |
| `dbxlab_synthetic` | Price book, inventory, customers | Synthetic, generated by `quote_ai.ingest.synthetic` | on demand | `quote_ai_sales_bronze.price_book_raw`, `inventory_raw`, `customer_raw` |

## GUDID (public)

- **Publisher:** U.S. FDA Global Unique Device Identification Database, distributed by the National Library of
  Medicine as AccessGUDID: <https://accessgudid.nlm.nih.gov/download> (files) and
  <https://accessgudid.nlm.nih.gov/resources/developers/v3> (API).
- **Files:** `AccessGUDID_Delimited_Full_Release_YYYYMMDD.zip` (pipe-delimited, monthly) and
  `gudid_daily_update_YYYYMMDD.zip` (daily), under `https://accessgudid.nlm.nih.gov/release_files/download/`. The
  download page lists an MD5 per release; every landed file's MD5 and SHA-256 are in `quote_ai_ops.ingestion_file`.
- **API:** `GET /api/v3/devices/history.json?di=...` (or `record_key`), which returns one entry per published
  version. AccessGUDID publishes no rate limit, so the API source is capped at 2 requests a second and 2,000
  requests per run, backs off on 429 and 5xx, and only looks up records that changed since its last successful run.
- **Terms:** public data. Check the AccessGUDID terms of use before redistributing it, and cite GUDID as the source
  in anything published.

## DBxLab (synthetic)

DBxLab Medical Supply is fictional. Its price book, stock and customers are generated, deterministic, and match the
Lakeside test fixtures (`tests/quote_ai/lakeside_fixtures.py`). They aren't real commercial data.

## Where it lands, and the audit trail

| Location | What |
| --- | --- |
| Volume `quote_ai_gudid_bronze.releases` | Landing zone: `<full\|daily>/<yyyymmdd>/`, each zip as published and its files beside it; never edited |
| Volume `quote_ai_sales_bronze.landing` | `dbxlab/<yyyymmdd>/`: the synthetic files |
| `quote_ai_ops.ingestion_log` | One row per run of a source: status, rows per table, load IDs, watermark, job run, identity, git commit, config hash |
| `quote_ai_ops.ingestion_file` | One row per landed file: path, URL, release date, size, MD5, SHA-256 |
| `quote_ai_ops.ingestion_config` | The config in force, with history (SCD type 2), joined to runs by `config_hash` |
| `quote_ai_ops.v_ingestion_audit` | From a load ID: the run, its files and its config entry |

Every bronze row carries `_source`, `_file_or_request`, `_load_id`, `_ingested_at` and `_release_date`.

Who started a job, and what changed in each table, come from Databricks' own audit tables: `system.access.audit`,
the job run history (linked through `job_id` and `job_run_id`), Delta table history, and Unity Catalog lineage.

Access: the ingestion jobs and pipeline run as the bundle's `run_as` (`sp-dbx-lakehouse` in dev-shared and prod).
No other principal is granted write access to the bronze or `quote_ai_ops` schemas, and reps aren't granted read access to
bronze.

**Retention:** the landing volumes and `quote_ai_ops.ingestion_file` are kept for the life of the project, because they are
the record of what was published. `quote_ai_ops.ingestion_log` is kept for at least a year.
