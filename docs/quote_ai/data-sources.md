# QuoteAI data sources

Every source is one entry in [`config/quote_ai/ingest/sources.yml`](../../config/quote_ai/ingest/sources.yml), loaded by the ingestion
framework (`src/quote_ai/ingest`, AI-02) into bronze. Raw landing and file-source Bronze ingestion remain unchanged.
The [glove category classifier](glove-classification.md) adds an ops snapshot/view and filters daily API candidates;
it is not a commercial Silver/Gold model or clinical eligibility check.

| Source | What | Where it comes from | Schedule | Bronze |
| --- | --- | --- | --- | --- |
| `gudid_full_release` | Every device in GUDID, current version | AccessGUDID delimited full release (pipe-delimited zip, about 400 MB, monthly) | once, or again to rebuild | `quote_ai_gudid_bronze.device_raw`, `identifiers_raw`, `device_sizes_raw`, `product_codes_raw`, `gmdn_terms_raw` |
| `gudid_daily_updates` | The device versions published that day | AccessGUDID daily update release (zip, not on every day) | daily | `quote_ai_gudid_bronze.daily_device_raw` |
| `gudid_api_device_history` | Published history for included glove-category daily keys | AccessGUDID REST API v3, device history | daily, after files and classification | `quote_ai_gudid_bronze.api_device_history` |
| `dbxlab_synthetic` | Price book, inventory, customers | Synthetic, generated by `quote_ai.ingest.synthetic` | on demand | `quote_ai_sales_bronze.price_book_raw`, `inventory_raw`, `customer_raw` |

## GUDID (public)

- **Publisher:** U.S. FDA Global Unique Device Identification Database, distributed by the National Library of
  Medicine as AccessGUDID: <https://accessgudid.nlm.nih.gov/download> (files) and
  <https://accessgudid.nlm.nih.gov/resources/developers/v3> (API).
- **Files:** `AccessGUDID_Delimited_Full_Release_YYYYMMDD.zip` (pipe-delimited, monthly) and
  `gudid_daily_update_YYYYMMDD.zip` (daily), under `https://accessgudid.nlm.nih.gov/release_files/download/`. The
  download page lists an MD5 per release; every landed file's MD5 and SHA-256 are in `quote_ai_ops.ingestion_file`.
- **API:** `GET /api/v3/devices/history.json?di=...` (or `record_key`), which returns one entry per published
  version. AccessGUDID publishes no rate limit, so the API source is capped at 2 requests a second and 2,000
  requests per run and backs off on 429 and 5xx. With the current classification config, it selects only included
  daily keys with exact source provenance and the current rule hash, before applying the cap; it never enriches
  every full-release device. The filtered path disables the release watermark for rule-change backfills but keeps
  the target-row completion cache. Missing/stale snapshots fail closed. See the [API gate and opt-out policy](glove-classification.md#daily-api-gate).
- **Terms:** public data. Check the AccessGUDID terms of use before redistributing it, and cite GUDID as the source
  in anything published.

## DBxLab (synthetic)

DBxLab Medical Supply is fictional. Its price book, stock and customers are generated, deterministic, and match the
Lakeside test fixtures (`tests/quote_ai/lakeside_fixtures.py`). They aren't real commercial data.

## Where it lands, and the audit trail

| Location | What |
| --- | --- |
| Volume `quote_ai_gudid_bronze.quote_ai_releases` | Landing zone: `<full\|daily>/<yyyymmdd>/`, each zip as published and its files beside it; never edited |
| Volume `quote_ai_sales_bronze.quote_ai_landing` | `dbxlab/<yyyymmdd>/`: the synthetic files |
| `quote_ai_ops.ingestion_log` | One row per run of a source: status, rows per table, load IDs, watermark, job run, identity, git commit, config hash |
| `quote_ai_ops.ingestion_file` | One row per landed file: path, URL, release date, size, MD5, SHA-256 |
| `quote_ai_ops.ingestion_config` | The config in force, with history (SCD type 2), joined to runs by `config_hash` |
| `quote_ai_ops.v_ingestion_audit` | From a load ID: the run, its files and its config entry |
| `quote_ai_ops.glove_classification` | Overwritten current category snapshot, including unknown/excluded, evidence and rule version/hash; not classification history |
| `quote_ai_ops.glove_devices` | Included-only category view; not latex-free or clinical/commercial eligibility |

Every bronze row carries `_source`, `_file_or_request`, `_load_id`, `_ingested_at` and `_release_date`.

Who started a job, and what changed in each table, come from Databricks' own audit tables: `system.access.audit`,
the job run history (linked through `job_id` and `job_run_id`), Delta table history, and Unity Catalog lineage.

Access: the ingestion jobs and pipeline run as the bundle's `run_as` (`sp-dbx-lakehouse` in dev-shared and prod).
No other principal is granted write access to the bronze or `quote_ai_ops` schemas, and reps aren't granted read access to
bronze.

**Retention:** the landing volumes and `quote_ai_ops.ingestion_file` are kept for the life of the project, because they are
the record of what was published. `quote_ai_ops.ingestion_log` is kept for at least a year.

## Silver, gold and the product model (AI-03)

Built from the bronze above by `resources/quote_ai/quote_ai_product_model.job.yml`: the `quote_ai_gudid` pipeline, then
`src/quote_ai/jobs/product_job.py` (`setup`, `seed`, `match`). Bronze is only read.

| Object | What | Truth |
| --- | --- | --- |
| `quote_ai_gudid_silver.device_history` | Every published version of a device (SCD type 2, AUTO CDC by record key and version) | Source |
| `quote_ai_gudid_silver.device` | The current version per device | Source |
| `quote_ai_gudid_silver.package`, `gmdn_term`, `product_code`, `device_size` | Child tables: package levels and quantities, GMDN, FDA codes, sizes | Source |
| `quote_ai_gudid_gold.device_distribution` | Current version, in distribution or not, and the day it left | Source |
| `quote_ai_gudid_gold.glove_devices`, `glove_packages` | Published devices in AI-02's glove category (`quote_ai_ops.glove_devices`), and their package levels | Source |
| `quote_ai_product.dbxlab_product`, `dbxlab_sku` | DBxLab's catalog: one SKU per product, size and selling unit (synthetic) | Business |
| `quote_ai_product.product_device_mapping` | SKU <-> GUDID device at its package level; method, confidence, verification status | Business once verified |
| `quote_ai_product.mapping_review_queue`, `sku_offerable` | What waits for a person; what can be offered | - |
| `quote_ai_sales.price_book`, `inventory_snapshot`, `customer` | Typed views over AI-02's synthetic bronze | Business |
| `quote_ai_sales.rep`, `quote_history` | Sales team; closed quotes with outcomes from a planted signal (`quote_ai.mock.catalog.SIGNAL`) | Synthetic |

**Demo binding.** DBxLab is fictional, so its SKUs have no real supplier. `match` gives each SKU a real GUDID glove
device as its supplier record (the first unused device by primary DI with a catalog number and a box of the SKU's
count), then matches on catalog number and package level. `--demo-verify` marks the high-confidence box matches as
verified by `demo:sales-ops`; every other level (each, case) waits in the review queue. Demo data only.

**Not yet an ingestion source.** The DBxLab catalog and reps are written by the product job from
`quote_ai.mock.catalog`, and since AI-12 the quote history, customer prices and inventory history by the win model's
job (`ml_job.py seed`, from `quote_ai.mock.generate_dbxlab`), not landed by the ingestion framework. Landing them through `dbxlab_synthetic` would mean
new tables in `config/quote_ai/ingest/sources.yml` and a change to `quote_ai.ingest.synthetic`: a reviewed change to
the framework, not part of AI-03. GUDID sterilization (`sterilization*.txt`) isn't a bronze table either; silver
uses `device_sterile` and `sterilization_prior_to_use` from `device.txt`.

## Season 4: search and knowledge (AI-15 to AI-17)

| Object | What | Truth |
| --- | --- | --- |
| `quote_ai_product.dbxlab_range`, `range_evidence` | The wider glove range G to R (`quote_ai.mock.range`): catalog-only, no price book or stock rows, with GUDID-like fields, AI-read values and demo:qa-verified spec and chemo rows | Synthetic |
| `quote_ai_product.catalog_skus`, `eligibility_evidence` | What the eligibility engine reads: DBxLab SKUs and the range; glove_evidence and the range evidence | Business when verified |
| `quote_ai_ai.sku_search_doc` -> `sku_search_index` | One row per sellable SKU; the AI Search index. Finds candidates, never decides | Search text holds claims |
| `quote_ai_ai.knowledge_chunks` -> `knowledge_index` | Chunks of the parsed supplier PDFs, GUDID descriptions, the playbook, GMDN notes and customer price sheets (`quote_ai.mock.knowledge`), each with its truth layer and account | Per chunk |
| `quote_ai_sales.rep_account` | Which accounts each rep owns: the knowledge retrieval filter | Synthetic |
| `quote_ai_eval.search_cases`, `eligibility_cases`, `comparison_cases` | The evaluation suites, loaded from `evaluation/quote_ai/v1` | Test data |

**Evidence the contract needed.** Since AI-15, `intended_use` comes verified from a device's FDA product code (LZA,
LYY, LYZ, LZC exam; KGO surgical) and `material` / `powder_free` from the spec sheets (verified through AI-09's five
checks); before, they existed only as AI-read values. The synthetic spec sheets carry the two new lines.

**Not an ingestion source.** The range, the knowledge texts and the rep accounts are written by the search and
knowledge jobs from `quote_ai.mock`, like the catalog. Landing them through `dbxlab_synthetic` would be a reviewed
change to the ingestion config and `quote_ai.ingest.synthetic` (not made).
